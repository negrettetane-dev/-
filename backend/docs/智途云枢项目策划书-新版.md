# “智途云枢”城市交通智能决策平台项目策划书

> 版本说明：本文部分章节保留早期单城市示范背景；当前实现已升级为北京、厦门、福州三城通用型智慧交通控制中心，最新接口与实现以 `api-contract.md` 和代码为准。

## 一、项目概况

### 1. 项目名称

“智途云枢”城市交通智能决策平台

### 2. 项目类型

智慧交通类软件项目、城市治理辅助决策平台、前后端分离式 Web 应用项目。

### 3. 项目定位

本项目面向城市交通治理与出行辅助场景，以福建宁德为示范城市，建设一个集交通态势感知、拥堵指数计算、拥堵趋势预测、路径推荐、事件预警于一体的智能交通决策平台。

当前项目已完成后端基础框架，采用 FastAPI 提供标准化接口，前端可基于接口实现交通大屏、地图展示、路线推荐页面和预警分析页面。项目后续可继续接入真实交通数据、天气接口、数据库和机器学习模型，逐步升级为更完整的智慧交通应用系统。

## 二、项目背景

近年来，城市交通压力不断增大，尤其在早晚高峰、产业园区通勤、商业区聚集、恶劣天气和突发事件影响下，道路拥堵和交通安全问题更加突出。传统交通管理方式主要依靠人工巡查、固定监控和事后处理，存在数据分散、响应滞后、预测不足、决策依据不够直观等问题。

宁德作为福建重要的新能源产业城市，产业园区、交通枢纽、主城区、商业中心之间的人流和车流联系紧密，城市交通运行状态对居民出行、园区通勤和城市治理效率都有直接影响。因此，建设一个能够综合分析交通数据并提供预测预警能力的平台，具有较强的现实意义。

本项目以“数据融合 + 智能预测 + 辅助决策”为核心思路，通过后端服务统一处理道路、车流、速度、天气、事件和 POI 等信息，形成可供前端展示和管理决策使用的数据接口。

## 三、项目建设目标

### 1. 总体目标

建设一个可运行、可展示、可扩展的城市交通智能决策平台，实现宁德城市交通状态展示、拥堵指数分析、趋势预测、路线推荐和事件预警，为城市交通治理和智慧出行提供数据支撑。

### 2. 阶段目标

第一阶段目标：完成项目后端骨架，提供稳定 API 接口，支持前端 Demo 展示。

第二阶段目标：完善前端页面，实现交通大屏、地图展示、预测分析、路线推荐和预警展示。

第三阶段目标：将样例数据迁移到 JSON 或数据库，提升数据维护能力。

第四阶段目标：接入真实天气、地图或交通数据，优化预测算法和路径算法。

第五阶段目标：完善部署、测试、文档和答辩材料，形成完整项目成果。

## 四、需求分析

### 1. 用户需求

交通管理人员需要快速掌握城市道路拥堵情况，及时发现高风险路段和突发事件。

普通出行用户需要了解道路通行状态，选择更快、更安全或更低拥堵的出行路线。

园区和企业管理者需要关注通勤压力，在高峰时段提前发布错峰出行或绕行建议。

项目评审或课程教师需要看到系统结构清晰、功能完整、接口规范、具有一定创新性和落地价值。

### 2. 功能需求

系统需要支持城市配置、交通态势汇总、路段状态查询、交通事件查询、拥堵趋势查询、拥堵预测、路线推荐和事件预警等功能。

### 3. 非功能需求

系统需要具备接口稳定、结构清晰、易于扩展、便于前后端协作、便于部署和便于演示的特点。

## 五、系统功能设计

### 1. 城市配置模块

该模块负责管理城市基础信息。当前默认支持 `ningde`，后续可扩展至福建省内更多城市。城市配置模块为其他接口提供统一城市参数，保证系统具备多城市扩展能力。

主要功能：

- 查询当前支持的城市列表。
- 返回城市名称、城市编码和可用状态。
- 为交通态势、路线推荐和预警接口提供城市参数。

对应接口：

- `GET /api/cities`

### 2. 交通态势汇总模块

该模块用于展示城市整体交通运行情况，包括全城拥堵指数、拥堵等级、平均速度、活跃事件数量、监测路段数量、拥堵路段数量和重点拥堵路段。

主要功能：

- 汇总当前城市交通状态。
- 计算整体拥堵指数。
- 统计重点拥堵路段。
- 为交通大屏首页提供核心指标。

对应接口：

- `GET /api/traffic/summary?city=ningde`

### 3. 路段状态模块

该模块用于展示城市重点路段的交通状态，包括道路名称、所属区域、经纬度坐标、平均速度、车流量、天气影响、事件影响、拥堵指数和拥堵等级。

主要功能：

- 查询重点道路实时或模拟状态。
- 根据路段数据计算拥堵指数。
- 支持前端地图按拥堵等级渲染不同颜色。

对应接口：

- `GET /api/traffic/segments?city=ningde`

### 4. 交通事件模块

该模块用于管理和展示道路交通事件，包括拥堵事件、天气事件和通勤压力事件等。

主要功能：

- 查询当前活跃交通事件。
- 返回事件类型、标题、等级、区域、位置和说明。
- 支持前端地图告警点和事件列表展示。

对应接口：

- `GET /api/traffic/events?city=ningde`

### 5. 拥堵趋势模块

该模块用于展示一天内不同时段的拥堵指数变化，为预测模型和前端趋势图提供数据基础。

主要功能：

- 查询指定城市的拥堵趋势。
- 支持折线图展示交通压力变化。
- 为预测模块提供趋势参考。

对应接口：

- `GET /api/traffic/trend?city=ningde`

### 6. 拥堵预测模块

该模块根据当前拥堵指数、历史趋势和高峰规则，预测未来一段时间的拥堵情况。当前版本采用规则模型，后续可升级为机器学习模型。

主要功能：

- 支持 15 至 180 分钟预测范围。
- 返回每 15 分钟一个预测点。
- 输出高风险路段、预测置信度和影响因素。

对应接口：

- `GET /api/prediction/congestion?city=ningde&horizon_minutes=60`

### 7. 路径推荐模块

该模块基于起点、终点和交通状态生成多策略路线推荐。当前版本支持最快路线、低拥堵路线和安全路线。

主要功能：

- 支持输入起点和终点 POI。
- 返回路线距离、预计耗时、拥堵评分、安全评分、路线坐标和出行建议。
- 满足不同出行目标下的路径选择需求。

对应接口：

- `GET /api/route/recommend?city=ningde&origin=ningde_station&destination=catl_industrial_zone`

### 8. 事件预警模块

该模块根据拥堵状态、天气因素和交通事件生成预警信息，为交通疏导和安全提示提供参考。

主要功能：

- 识别活跃交通风险。
- 生成预警等级和处置建议。
- 支持前端预警弹窗、列表和大屏提示。

对应接口：

- `GET /api/warning/active?city=ningde`

## 六、技术方案

### 1. 技术架构

项目采用前后端分离架构。后端负责数据处理、算法计算和接口输出；前端负责页面展示、地图可视化、图表展示和交互操作。

当前仓库主要包含后端部分，技术栈如下：

| 模块 | 技术 |
| --- | --- |
| 后端框架 | FastAPI |
| 数据校验 | Pydantic |
| 接口文档 | Swagger UI |
| 测试工具 | Pytest、FastAPI TestClient |
| 数据来源 | Python 内置模拟数据 |
| 算法方式 | 规则融合算法、趋势预测规则 |
| 部署方式 | 本地 Uvicorn，后续可扩展 Docker |

### 2. 后端目录结构

| 目录或文件 | 作用 |
| --- | --- |
| `app/main.py` | FastAPI 应用入口，注册接口路由和跨域配置 |
| `app/api/` | 接口层，负责处理前端请求 |
| `app/services/` | 业务逻辑层，负责交通、预测、路线和预警服务 |
| `app/algorithms/fusion.py` | 拥堵指数计算和拥堵等级划分 |
| `app/models/schemas.py` | 数据模型定义 |
| `docs/api-contract.md` | 前后端接口契约 |
| `docs/backend-roadmap.md` | 后端开发路线 |
| `tests/test_api.py` | 接口测试用例 |
| `requirements.txt` | 项目依赖 |

### 3. 拥堵指数计算方案

当前项目根据平均速度、车流量、天气因素和事件因素计算拥堵指数。计算结果控制在 0 到 100 之间，数值越高表示拥堵越严重。

拥堵等级划分：

| 拥堵指数 | 拥堵等级 |
| --- | --- |
| 0-35 | 畅通 |
| 35-60 | 缓行 |
| 60-80 | 拥堵 |
| 80-100 | 严重拥堵 |

该方案简单直观，适合 Demo 展示和前期验证。后续可通过真实历史数据训练模型，提高预测准确性和算法可信度。

### 4. 数据设计

当前系统数据包括：

- 城市数据：城市编码、城市名称、支持状态。
- 路段数据：道路编号、名称、区域、坐标、平均速度、车流量、天气因素、事件因素。
- 事件数据：事件编号、类型、标题、等级、区域、位置和描述。
- 趋势数据：时间点和拥堵指数。
- POI 数据：宁德站、万达广场、新能源产业园区、蕉城中心等。

后续数据可从 Python 文件迁移至 JSON 文件，再进一步迁移至 PostgreSQL 数据库。

## 七、项目特色与创新点

1. 面向真实城市治理场景：以宁德交通运行和园区通勤为示范，具有明确应用背景。
2. 多源数据融合：综合速度、流量、天气和事件因素计算拥堵状态。
3. 预测与预警结合：不仅展示当前状态，还提供未来拥堵预测和事件预警。
4. 多策略路线推荐：从最快、低拥堵、安全三个角度提供路线方案。
5. 接口规范清晰：通过接口契约降低前后端协作成本。
6. 可扩展性较强：保留城市参数，后续可扩展多城市、多数据源和数据库。

## 十三、风险分析与解决方案

### 1. 数据真实性不足

风险说明：当前项目主要使用模拟数据，展示效果可能与真实交通情况存在差异。

解决方案：Demo 阶段明确标注数据模式为 simulation，后续逐步接入真实天气、地图和交通数据。

### 2. 预测准确率不高

风险说明：当前拥堵预测采用规则模型，复杂交通环境下准确率有限。

解决方案：后期采集历史交通样本，引入机器学习模型，并建立预测效果评估指标。

### 3. 前后端接口不一致

风险说明：如果接口字段频繁变化，可能导致前端页面报错。

解决方案：维护接口契约文档，接口变更前先沟通，新增字段保持向后兼容。

### 4. 项目分工不均

风险说明：部分成员任务较重，可能影响进度。

解决方案：按模块划分任务，每周检查进度，必要时由项目负责人重新分配工作。

### 5. 展示效果不足

风险说明：仅有后端接口可能不够直观，影响答辩效果。

解决方案：前端优先完成大屏、地图、趋势图和路线展示，让功能可视化。
